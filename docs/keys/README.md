# Published signing keys

BreakPoint reports can carry an ed25519 attestation (see `docs/attest.md`). To check
one you need the signer's **public** key. This directory is where Inoki Labs
publishes its key.

## Inoki Labs key

Ratings that Inoki Labs ran itself are signed with `"signer": "inoki"`. The public
key will be published in two places that must agree:

1. On the site, at the fixed path `/keys/inoki.pub`
   (https://breakpoint-inoki.vercel.app/keys/inoki.pub).
2. In this repository, as `docs/keys/inoki.pub`.

**No key is published yet.** An Inoki Labs maintainer generates the keypair on their
own machine and holds the private key. It is never generated by tooling on their behalf and
never stored in any repository. Until `inoki.pub` exists here and on the site, no
report can be verified as an Inoki rating.

To publish (Inoki Labs maintainers only):

```
breakpoint keys new --out ~/.breakpoint/keys --name inoki   # outside every repo
cp ~/.breakpoint/keys/inoki.pub docs/keys/inoki.pub          # public half only
# and copy the same file to breakpoint-web/public/keys/inoki.pub
```

Commit the `.pub` file and record its `key_id` (printed by `keys new`) below. If the
key is ever rotated, keep the old public key as `inoki-<key_id>.pub` so older
ratings stay verifiable, and say here which key_id is current.

| key_id | status | published |
|--------|--------|-----------|
| (none yet) | | |

## Verifying an Inoki rating

```
curl -O https://breakpoint-inoki.vercel.app/keys/inoki.pub
breakpoint verify rating.json --pubkey inoki.pub
```

Check that the downloaded file is byte-identical to `docs/keys/inoki.pub` in this
repo. Two independent channels make a swapped key on one of them visible.

## Team keys ("self")

A team signs its own CI or local runs with its own key (`--signer self`) and
publishes that `.pub` wherever its consumers already trust (its own repo or site).
A "self" signature proves the team produced the exact report, nothing more.
